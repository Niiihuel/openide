# OpenIDE 1.3.0

OpenIDE 1.3.0 adds durable Markdown memory, improves project indexing and CLI tool discovery, and fixes the Linux update download and recovery path. The editor remains based on Code OSS 1.136.1.

## Memory you can inspect

The agent can search, read, save and forget Markdown memories, with explicit controls for automatic and manual capture. A persisted capture queue resumes unfinished work and avoids duplicating already applied notes. Memory stays connected to the project's code graph and keeps workspace boundaries, trust checks and user edits intact.

## Project indexing and CLI tools

File indexing uses bounded reads and batches, retries failed work, and avoids rebuilding the whole graph for individual manifest changes. Queries reuse generation-aware caches and return bounded results.

Dock CLIs can discover the IDE's tools through a capability catalog and focused tool groups. Claude's session hook introduces the available tools, and connection diagnostics distinguish a configured connection from a live one. Existing CLI authentication is reused. A real authenticated Claude session exercised memory discovery, saving and recall; CI uses credential-free fixtures.

## Agent execution and recovery

The agent runtime separates provider transport, turn execution and native services. Ordered run journals record requests, tool intents and results; interrupted effects are reported as uncertain instead of being replayed automatically. Tool permissions and workspace ownership apply to nested operations and subagent worktrees.

Run-journal recovery and process confinement remain experimental. Linux confinement requires bubblewrap when enabled; Windows and macOS do not yet provide the same operating-system isolation. CLI tool exposure continues to use the existing window-scoped connection model.

## Update reliability

Linux downloads now consume the binary buffer inside each VSBuffer chunk. The updater verifies the final copied artifact before replacement, preserves the previous healthy installation, and refuses another install while startup confirmation is pending. Recovery replaces the executable atomically. Kernel-managed locks release after crashes, and repeated CLI invocations do not cause a premature rollback.

Windows discards a corrupt cached installer and downloads it again before reporting the update ready. Regression coverage exercises download integrity, interrupted replacement, process death, recovery, and a real Electron restart with a signed test release.

### Installing from OpenIDE 1.1.0 or 1.2.0 on Linux

The published AppImages of those versions have a broken update download path. **Install 1.3.0 manually once**; the fix cannot download itself through the old broken updater.

Download the AppImage from this release and follow the [manual installation steps](../updates.md#manual-upgrade-from-the-published-110--120-appimages). On NixOS, regenerate the launcher with the 1.3.0 installer script; the new recovery protocol requires `flock` from util-linux. Close OpenIDE before replacing the installation.

Linux x64/arm64 and Windows x64/arm64 packages are built by the release workflow. Automatic feeds cover Linux x64 AppImage and Windows user installers. Native Windows installer execution still requires platform validation; macOS release packaging remains disabled.
