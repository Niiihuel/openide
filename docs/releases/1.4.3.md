# OpenIDE 1.4.3

OpenIDE 1.4.3 completes the integration between portable Agent Skills, project instructions and Agent Plugins without changing the 1.4 feature line. Existing OpenIDE customizations remain compatible while the standard layouts become the preferred paths for new content.

## Skills and project instructions

- Skills created by the agent now use the portable `.agents/skills/<name>/SKILL.md` layout, while existing `.openide/skills` and legacy global skills remain readable.
- Enabled plugin skills join the same progressive-disclosure index with namespaced identities and read-only ownership.
- Standard `AGENTS.md` and `AGENTS.override.md` instructions are loaded alongside OpenIDE rules, with global-first ordering, bounded prompt budgets and workspace-trust enforcement.
- The Skills settings surface links directly to plugin management and identifies plugin-provided skills clearly.

## Portable plugins and marketplaces

- The Create Plugin workflow emits an Agent Plugins v1 root manifest, portable skills and MCP configuration, and host-specific Copilot resources in their sanctioned namespace.
- Local `.agents/plugins/marketplace.json` catalogs and legacy Codex `.codex-plugin/plugin.json` manifests are recognized alongside the existing plugin formats.
- Installed plugin metadata now lives in a file-backed versioned store and preserves the exact source descriptor needed to restore immutable releases after restart.
- Git, npm and pip installations use staged promotion, deterministic tree digests, provenance receipts and rollback protection instead of mutating the active install in place.

## Signed plugin registry

- HTTPS registries can publish immutable Ed25519-signed plugin releases through a strict catalog and artifact protocol.
- OpenIDE verifies registry origin, publisher identity, release signature, artifact size and SHA-256, every file digest and extraction path before atomically promoting an install.
- Registry updates preserve exact release metadata, respect marketplace allowlists and auto-update policy, and never fall back to Git semantics.
- A dependency-free reference registry server and publisher CLI are included under `dev/plugin-registry`, with draft, staging, publication, rollback, yank and replay-protection coverage.

Automatic update feeds cover the Linux x64 AppImage and Windows x64/arm64 user installers. Linux arm64 packages remain available for direct download.
