# OpenIDE 1.2.0 release review

Reviewed the Code OSS 1.136.1 integration, OpenIDE agent changes and the signed
GitHub release/update path. This is a change review with targeted integration
checks, not a full security audit of every upstream source or dependency.

## Findings resolved

- Stable feeds previously advertised private draft release assets. Promotion now
  verifies signed manifests and downloaded installers, publishes the release,
  checks unauthenticated download access, then advances the feed.
- Update detection showed an indicator without automatically opening its
  popover. Actionable updates now announce once per version/window session,
  defer while the window is inactive and preserve keyboard focus.
- Linux updater restart did not invoke the mutable AppImage launcher. It now
  relaunches through the installed wrapper or AppImage instead of an old
  extracted executable.
- The AppImage health confirmation helper was never called. A ready workbench
  now confirms its running version and the installed hash before removing
  recovery metadata. An older running instance cannot acknowledge a new binary.
- Disabling updates could leave Linux requests running. Checks ignore late
  cancelled responses and download cancellation waits for temporary-file cleanup.
- The release runner's disk cleanup removed the Node 24 toolchain installed by
  setup-node, causing a fallback to Node 22. The tool cache is now preserved.
- Existing icon generator scripts needed to be preserved in the new upstream
  JavaScript allowlist.
- An upstream Unicode regex literal failed the production minifier's ASCII
  check. It now uses an equivalent Unicode escape, with a source audit in CI.
- The bundled main process imported the external `semver` package before ASAR
  module resolution was enabled, preventing packaged startup. It now uses the
  existing bundled semver implementation. Release builds audit static imports
  in all three bootstrap entry points.
- The packaged welcome screen omitted its SVG logo. The shared asset is now
  included for every desktop platform; Linux release jobs run a packaged UI
  smoke test before creating release assets.
- The upstream migration introduced unused CLI download-route helpers that
  referenced a removed method and omitted fork-specific architectures. They
  were removed: OpenIDE retains its existing OS/architecture release routing.
  CI now checks the native Rust CLI as well as the editor.
- Windows packaging now adds the installed SDK tools to `PATH` before the
  build. The upgraded Code OSS pipeline invokes `signtool.exe` when preparing
  native dependencies, even for unsigned installers; previously it failed
  during packaging because the SDK's versioned directory was not discoverable.

## Validation

- 715 common and repository-contract tests.
- 242 agent browser tests.
- 10 request transport tests, including binary audio; one platform-specific skip.
- 8 Electron update indicator/popover tests.
- 38 Electron main-process updater tests, including AppImage recovery and health.
- 5 signed release-feed verification tests; 11 build/audit/synchronization tests.
- Client typecheck, branding/version checks and workflow lint.
- Isolated real Electron startup: welcome layout, bundled extensions, chat draft
  preservation and Zen enter/exit with Electron 42.10.0 / embedded Node 24.18.1.
- Production minification and Linux x64 packaging, including bootstrap imports.
- Automatic update announcement in the packaged app: an isolated profile reports
  an older product version and checks the real signed stable feed. The popover
  appears after startup while preserving composer focus and its draft.
- [Release build](https://github.com/Niiihuel/openide/actions/runs/33939597061):
  Linux x64/ARM64 and Windows x64/ARM64 completed successfully, including the
  packaged Linux startup checks.
- [Stable promotion](https://github.com/Niiihuel/openide/actions/runs/33942198771):
  verified the signed feed and artifact hashes, published 54 release assets,
  then updated the stable feed. The release is public and marked latest.
- Independent public-feed checks verified Ed25519 signatures for all three
  automatic-update targets and confirmed HTTP 200 downloads with the expected
  sizes. An installed 1.1.0-to-1.2.0 download/restart was not exercised in this
  publication check.

The build uses Node 24.18.0. OpenIDE's product version is independent of the
Code OSS API version used for extension compatibility. Automated checks do not
prove every third-party extension or provider works.

## Remaining validation and dependency findings

An installed 1.1.0 binary predates the automatic popover and AppImage relaunch
fixes. Its update indicator can initiate the download; the first restart may
need the installed launcher. Changes in 1.2.0 cannot retroactively repair code
already running in 1.1.0. Development builds intentionally disable updates.

Cross-platform packaged installation must be checked separately from compilation;
Linux test results do not establish Windows installation behavior. macOS is not
in the release matrix.

`npm audit --omit=dev` on the migrated editor reports three advisories affecting
five dependency entries (two high and three moderate entries; no critical):

- `adm-zip`, through `foundry-local-sdk`: crafted ZIP memory exhaustion
  ([GHSA-xcpc-8h2w-3j85](https://github.com/advisories/GHSA-xcpc-8h2w-3j85)).
- `@anthropic-ai/sdk`: filesystem memory-tool permissions
  ([GHSA-p7fg-763f-g4gf](https://github.com/advisories/GHSA-p7fg-763f-g4gf)).
- `uuid`, through `@microsoft/dev-tunnels-connections`: buffer bounds checking
  ([GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq)).

These upstream dependencies have not been upgraded here: npm proposes major SDK
changes for two chains and no direct fix for the tunnel chain. Their usage and
API compatibility need a separate dependency update; this release does not
claim to eliminate all dependency advisories.
