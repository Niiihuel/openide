All builds come from the [GitHub Releases page](https://github.com/Niiihuel/openide/releases). Each release ships the artifacts together with `.sha256` checksum files and a signed update manifest; verify the checksum before installing anything you downloaded by hand.

## Linux

### AppImage (recommended)

The AppImage is the only Linux format that the integrated updater can replace by itself. Download `OpenIDE-<version>-x86_64.AppImage`, make it executable and run it:

```bash
chmod +x OpenIDE-*.AppImage
./OpenIDE-*.AppImage
```

The supported mutable installation lives in `~/.local/bin/OpenIDE.AppImage`. When an update is installed the new file is written as `.pending`, the previous one is kept as `.previous` and a health marker is written; if the first launch of the new version fails, the wrapper restores the previous version once. See [Updates](/docs/updates/).

### Tarball

`OpenIDE-linux-<arch>-<version>.tar.gz` contains the generic Linux build. Extract it anywhere and run the entry point:

```bash
tar -xzf OpenIDE-linux-x64-*.tar.gz
./OpenIDE-linux-x64/bin/openide
```

The `bin/openide` launcher is what package managers put on your `PATH`.

### Packages

The release workflow also produces `.deb` and `.rpm` packages built from the same tree. Install them with your package manager:

```bash
sudo dpkg -i openide_*.deb     # Debian, Ubuntu and derivatives
sudo rpm -i openide-*.rpm      # Fedora, RHEL, openSUSE
```

Package installs are updated by your package manager, not by the built-in updater.

### NixOS

A derivation under `/nix/store` is never modified automatically, so on NixOS the mutable AppImage in `~/.local/bin` is the supported path. The repository ships an FHS sandbox for running and building the product:

```bash
nix-build dev/openide-fhs.nix -o result-fhs
./result-fhs/bin/openide-build -c './VSCode-linux-x64/openide --user-data-dir ~/.config/OpenIDE'
```

`dev/install-appimage.sh` installs the AppImage into the supported location and wires the wrapper.

## Windows

Download the installer from the latest release and follow the wizard. During setup you can enable *Add "Open with OpenIDE" action to Windows Explorer file context menu*; on Windows 11 the entry may be hidden behind *Show more options* (Shift + right-click).

Windows installers are currently published **unsigned** because an Authenticode certificate has to be bought from a CA. Auto-update still works (the updater verifies its own Ed25519 signature and the artifact hash), but SmartScreen and Windows Defender may warn when you download the installer manually. Verify the SHA-256 published next to the release and see [Troubleshooting](/docs/troubleshooting/#windows-defender-flags-the-installer-as-malware).

Group Policy deployments read from `HKLM\SOFTWARE\Policies\OpenIDE\OpenIDE`; see the [Windows section of Troubleshooting](/docs/troubleshooting/#windows).

## macOS

No signed macOS build is published yet. The source compiles and runs on macOS; see [Building OpenIDE](/docs/building/).

## Server and remote archives

Each release also contains `openide-reh-<platform>-<arch>-<version>.tar.gz` (the remote host used by SSH and WSL workflows) and `openide-reh-web-…` (the server behind `openide serve-web`). They are explained in [Other resources](/docs/other-resources/).

## Verify a download

```bash
sha256sum -c OpenIDE-1.121.1-x86_64.AppImage.sha256
```

The checksum files are generated by the release workflow from the exact bytes that were uploaded.
